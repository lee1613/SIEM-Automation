## 2026-09-24/25 — v0.4.5 full run — 24/50 (stopped before Q328–Q333)

Run: `log/v0/v0.4/v0.4.5_glm-5.3_full_r1` · 6,900 pts · $44.95 · 11.3 h question time.
Outcomes: 24 correct, 4 wrong answers submitted, 22 refusals.

### Root causes (26 questions, 10,000 points)

| # | Root cause | Questions | Points |
|---|---|---|--:|
| A | **Held the right answer, never submitted it.** The candidate was `solved`, but the premise gates (F2, C3, C7) kept rejecting ANSWER while premises were still being verified, and the turn or round budget ran out. | Q300, Q309, Q312, Q315, Q316, Q317, Q326 | 2,700 |
| B | **Cross-question contamination.** An earlier question's wrong or unsettled conclusion, carried by memory or the case file, steered a later one. | Q221, Q308, Q310, Q311, Q320, Q322 | 2,200 |
| C | **No working web search.** The answer is only on a vendor website (Symantec). See below. | Q213, Q302 | 200 |
| D | **Search miss.** Never found the right evidence: wrong host, wrong phase of the attack, or no candidate at all. | Q223, Q301, Q304, Q306, Q318, Q321, Q324 | 2,300 |
| E | **Right evidence, wrong value.** Off-by-one, ordering semantics, answer format, image misread. | Q202, Q212, Q216, Q217 | 2,600 |

Q221 (B) also held the exact answer among two unreconciled candidates. Counting it with A, 8
refused questions held the exact official answer (2,800 pts); 3 more had the right lead with a
slightly wrong value (Q202, Q212, Q321). Of the 22 refusals, 20 ended on the turn or round
budget and only 2 (Q213, Q301) on an explicit `NOT_FOUND`.

### Root cause C in detail: the agent has no working web search

`web_lookup` (`agent/v0/web_tool.py`) scrapes DuckDuckGo's HTML endpoint. It now returns
`web_lookup: no result snippets found.` for every query (re-tested 2026-09-28 with
"Ubuntu 16.04 codename"), so the agent has no web access in practice, although the tool is bound.

- **Q213** (Symantec severity of JSCoinminer): the senior recalled "Very Low" from memory, marked
  it unverified, and planned a `web_lookup` for the next round; the round hit its 10-iteration cap
  first. SH ended with `NOT_FOUND`.
- **Q302** (Symantec discovery date of the malware): the senior never called `web_lookup`; it
  recalled `07/20/18` from memory, flagged it "web_lookup was unavailable", and SH refused.
  Official: `11/11/16`.
- **Q223** (Ubuntu codename): `web_lookup` was called 4 times; at least 2 returned no snippets.
  The question stayed in D because the host's release was never pinned down either.

v0.2's Q332/Q333 (CVE identification) depended on the same tool and worked, so the scraper broke
between 2026-07 and 2026-09. It also threatens the unreached Q328–Q333.

### Reliability faults (not score causes; fixed in v0.5.0 R5–R8)

- A senior's context grew past its window inside a round (the check ran only between rounds);
  the provider stalled and returned 502s (Q328).
- One brief network drop made SH give up on a question (Q218, Q219, redone).
- A Windows file lock crashed the runner (Q311).
- A stalled call could hang 8–20 minutes before failing.

### What resolves each cause

| # | Fix | Target version |
|---|---|---|
| A | Make premise verification cheaper once the answer is in hand, without loosening F2 (e.g. verify only load-bearing premises, stop new premises after a `solved` candidate). | v0.5.1 |
| B | Memory must carry a question's verdict state; unsettled or wrong conclusions are not reused as premises. | v0.5.1 |
| C | Replace the DuckDuckGo scraper with a search API that returns results, plus a contract test that fails when it returns nothing. | v0.5.1 |
| D, E | Per-question: host/phase disambiguation, read every candidate image before choosing, answer-format checks. | v0.5.x |
| Faults | R5–R8. | v0.5.0 |
