## Plan A — Grounded Verification Pipeline (recommended core, lowest risk)

**Thesis**: v1.1's cheapest, most certain wins are the ~3,600 pts lost *after* the correct value
was already in hand or reachable (JOINER 2,300 + REASONING 800 + EXTRACTOR 500). Fix the pipeline
so evidence cannot be dropped, mangled, or fabricated between the worker and the scoreboard.

### A1. Evidence-grounded Joiner (anti-fabrication contract)
- Joiner prompt rewritten: `FINAL ANSWER` must be accompanied by
  `EVIDENCE: task=<n> quote="<verbatim substring from that task's result>"`.
- Deterministic guard in `joiner_node`: if the final answer string does not appear verbatim
  (case-insensitive) in any task result or the question text, the answer is tagged
  `ungrounded=true` → forces one replan round; if still ungrounded, the joiner must fall back to
  the best PARTIAL candidate quoted verbatim rather than a free-form synthesis.
- Explicit rule: "If the final delegation failed/empty, you MUST NOT invent a value. Choose the
  best evidence-backed candidate from earlier tasks or answer UNKNOWN."
- Directly targets Q211, Q221, Q225, Q303, Q312, Q331, Q333 (transcription slips like
  1367.875→1369.875 become impossible: value is copied, not re-typed).

### A2. Verifier role (new, cheap)
- New node between Joiner and Extractor: a GLM-5.2 worker in "verify mode" receives
  {question, candidate answer, evidence SPL} and runs ≤3 confirmation queries with one job:
  *prove or refute*. Refuted → one targeted replan with the refutation attached.
- Catches the SENIOR-REASONING class: wrong-timestamp "first" (Q212), unconfirmed-mining verdict
  (Q210 — which also would have prevented the Q216 cascade), literal-"None" group (Q308).
- Budget-gated: only runs for questions ≥ 500 pts (see A6).

### A3. Iteration-cap discipline + raw-content path
- When a Senior hits `MAX_ITER`, the forced final message must emit
  `PARTIAL ANSWER + evidence collected so far` — never a bare guess (Q328, Q332, Q333).
- New tool `get_raw_events(sourcetype, filter, limit≤20)` exempt from the aggregation-only verify
  rule, for content questions (email bodies, scripts, HTTP payloads): Q306, Q310, Q315, Q321, Q322.
  The verify gate keeps rejecting unaggregated `run_splunk_search`, so the exemption is explicit
  and bounded.
- Prompt patch on noise-filtering: "Never exclude processes/files by a benign-looking-name
  blocklist; suspicion comes from behavior, not names" (Q317 excluded `HxTsr.exe` by regex).

### A4. Answer-shape contract (planner → extractor)
- Planner derives an explicit `EXPECTED SHAPE` from `answer_guidance` at plan time (e.g. "bare
  model number, no vendor/suffix", "comma-separated lowercase list, no spaces").
- Extractor receives the shape + a deterministic post-pass: lowercase-compare is the scoreboard's
  own rule (`lower().strip()`), so casing never matters, but list ordering/spacing and suffix
  stripping do. Fixes Q202-class near-misses.

### A5. Web-knowledge tool
- One `web_lookup(query)` tool (Tavily or plain DuckDuckGo HTML fetch) exposed to Senior workers
  and the Verifier. Targets Q213, Q302 directly (200 pts, otherwise unsolvable) and materially
  helps CVE mapping on Q332/Q333 (2,000 pts) — "SuiteCRM RCE 2018" or "Ubuntu 16.04.4 kernel
  privilege escalation eBPF CVE" are one search away.

### A6. Points-aware budget
- ≥500 pts: MAX_ITER 15→25 per Senior, Verifier enabled, replan rounds 3→4.
- 100 pts: current budget.
- Rationale: 46/56 questions got identical effort in v1.1; the eight 1000-pt questions carry
  8,000 of 22,900 available points.

### A7. Truthful status classification
- `solved` only if a `FINAL ANSWER:` tag exists; empty/mid-stream transcript → `failed`;
  cap-hit → `partial` + `cap_hit=true`. (v1.1's 70% "solved" rate is inflated.)

**Cost impact**: +1 verifier call and occasional +1 replan on ~25 high-value questions, still on
GLM pricing. Est. total run cost $0.9–1.2 (vs $0.63).
**Expected recovery**: JOINER 2,300 + REASONING 800 + EXTRACTOR 500 + KNOWLEDGE 200 + partial
SENIOR-SEARCH (content path + cap discipline ≈ 1,500–2,500) → **realistic target 34–38/56,
~12,000–13,500 pts.**

## Plan B — Case-File Blackboard + Failure-Handoff + Specialist Workers (updated 2026-07-08 against run_1.2 evidence)

> **What run_1.2 (Plan A implemented) changed about this plan**
> (evidence: `log/v1/run_1.2/` — events.jsonl, metrics.json, per-question `questions/*.json`;
> LangSmith `botsv3-run_1.2`, p50=124s, p95=760s, 0 errored root traces):
>
> - **Fabrication is cured, selection is the new disease.** The grounding guard held on all
>   four v1.1 fabrication cases, but 9 questions (**5,100 pts**: Q210, Q215, Q221, Q318, Q321,
>   Q323, Q324, Q329, Q331) were lost with a correct, grounded candidate *already sitting in a
>   delegation's answer* while the joiner picked a different grounded-but-wrong one. That
>   selection problem is Plan C's job; Plan B's job is to make the candidates durable and
>   auditable so C has something to rank.
> - **The cost blowup is a search-failure symptom.** 103 of 204 delegations hit their iteration
>   cap, 62 failed outright (v1.1: 1), and every failed/too_big delegation triggered a blind
>   fresh-context replan — that is where 28.2M GLM input tokens ($26.53, 85% of run cost) went.
>   The case file + failure handoff is now primarily a **cost and search fix**, not a memory fix.
> - **SENIOR-SEARCH is still the largest block (4,900 pts)** and its texture is sharper now:
>   workers repeatedly *identified the right sourcetype then capped out before reading raw
>   events* (Q303: password `ilovedavidverve` sits in cloud-init events; workers found the
>   sourcetype and died at the cap), abandoned multi-hop chains halfway (Q306 NAT mapping,
>   Q216 duration eval), or scoped to one host and stopped (Q208, Q211, Q330).

### B1. Structured case file + candidate ledger + failure handoff
- SQLite/JSON store: `entities` (hosts, users, IPs, domains, files, hashes, buckets, CVEs),
  `findings` (claim, evidence SPL, source qid, **status: verified | hypothesis | refuted**,
  confidence), `attack_timeline` rows. SH planner gets a rendered digest instead of raw message
  history (complements the v1.2 `MAX_HISTORY_MSGS=24` window, which capped SH cost but does
  nothing for Senior workers).
- **NEW — candidate ledger**: per question, every delegation's answer is recorded as a
  *verbatim field value* + evidence quote + SPL + method. The joiner must choose FROM the
  ledger — copy, never re-type. Kills the value-mangling class outright: Q215
  (`BSTOLL-L.froth.ly` truncated to `BSTOLL-L`), Q221 (`nullweb_admin` → `web_admin`),
  Q315 (`definitelydontinvestigatethisfile.sh` → `sh`), Q331 (`1367.875` → `1368` recorded
  verbatim at capture time, not re-derived at synthesis time).
- **NEW — failure handoff**: when a delegation ends failed/too_big/cap_hit, emit a structured
  handoff digest (sourcetypes tried, SPL that returned data vs. empty, partial findings,
  where the trail went cold) and feed it to the replacement worker. Directly attacks the
  62-failed-delegation / 103-cap-hit replan loop: worker #2 resumes the hunt instead of
  re-running the same discovery searches. This is the single biggest cost lever in the plan —
  target is `failed_delegations` back toward v1.1's ~0 and Senior input tokens cut by >50%.
- Cascade killer unchanged: carried-forward claims arrive labeled `hypothesis` until promoted.

### B2. Phase-0 recon pass (run once, before the question loop)
- 4–6 parallel Senior workers build the incident skeleton: sourcetype inventory with event-count
  time ranges, key hosts + roles, the phishing waves, C2 infrastructure, cloud story. Written into
  the case file as verified baseline (~10 min wall).
- **Re-confirmed by run_1.2**: Q310 (500) chased the wave-2 `.lnk` artifact instead of the
  wave-1 `Frothly-Brewery-Financial-Planning-FY2019-Draft.xlsm` phishing attachment — exactly
  the wave-confusion recon prevents. Q329 (1000) answered `Beer` from the wrong uploaded file;
  a recon narrative of "which files were uploaded, by whom, what's in them" scopes that hunt.

### B3. Specialist worker types (same v0 graph, different prompt + tool config; router = one line in planner output)
| Specialist | Config delta | run_1.2 evidence |
|---|---|---|
| **Hunter** (default) | current Senior + **scope-first rule**: enumerate ALL hosts/users with a `stats by` before filtering to one | Q208 (`chrome#5` never found — searched one host), Q211 (counted 1 of 6 mining destinations — one host), Q330 (ranked 3 VPN users, `mkraeusen` never enumerated) — 1,200 pts |
| **Content-Inspector** | `get_raw_events` first-class; mandate: *drill to raw events FIRST, map sourcetypes second* | Q303 (password in cloud-init raw events; workers ID'd sourcetype then capped), Q315, Q321, Q322, Q328 — 2,600 pts |
| **Metrics-Analyst** | SPL-native stats (`perc25/perc75`, `eval`) mandatory; show formula + inputs; obey "using Splunk commands only" constraints literally | Q206 (2.9348 rounded up), Q216 (duration eval chain never completed), Q224 (avg over wrong candidate set), Q331 (manual Tukey beat Splunk `perc` worker) — 2,600 pts |
- Planner tags each task `[HUNTER]` / `[CONTENT]` / `[METRICS]`; executor picks the graph.

### B4. Hint economy
- `ScoreboardClient`/`LocalScoreboard` extended: `buy_hint(number)` deducts `HintCost` from that
  question's earned points (honest scoring, matches official CTF rules).
- Policy: confidence low after round 2 **and** points ≥ 500 → buy hint 1, replan with it.
  97 hints remain completely unused after two full runs. run_1.2's honest-refusal questions
  (Q328: no evidence found after 5 delegations; Q303) are exactly the profile where a 10–25 pt
  hint converts a 0 into 475–990.

**Cost impact**: recon ~$0.10 at GLM pricing; the failure handoff should *reduce* run cost
substantially (run_1.2's $31.36 was dominated by cap-hit workers rediscovering context —
target back under ~$5/run).
**Expected recovery**: attacks SENIOR-SEARCH 4,900 + scope-reasoning share of
SENIOR-REASONING (~1,100 of 2,600) + PLAN 500 structurally, and supplies the candidate
ledger Plan C needs → **with C, realistic target 38–44/56.**

## Plan C — Evidence-Ranked Adjudication + Dual-Track + Escalation (updated 2026-07-08 against run_1.2 evidence)

**Thesis (revised)**: v1.1's disease was fabrication; Plan A cured it. run_1.2's disease is
**selection**: on 9 questions (5,100 pts — Q210, Q215, Q221, Q318, Q321, Q323, Q324, Q329,
Q331) a correct candidate existed in some delegation and the joiner chose a different
grounded-but-wrong one. The grounding guard cannot help here — the wrong picks were *also*
grounded (Q324's `T-Mobile`, Q318's `Canada` both appear verbatim in evidence). Selection today
is recency/fluency/status-label driven:

- Q318: picked a later **partial** delegation's `Canada` over a **solved** delegation's `Russia`.
- Q331: picked the worker that computed Tukey's fences *manually* (`1499.25`) over the worker
  that used Splunk `perc25()/perc75()` (`1367.875` → `1368`) — despite the question saying
  "using Splunk commands only".
- Q324: worker #95 wrote "Verizon Wireless" (IP-geolocation inference); SH submitted `T-Mobile`.
- Q323: worker #1 had exactly `ABUNGST-L,FYODOR-L`; SH took worker #2's three-host superset.
- Q321: after REPLAN found nothing new, the fallback submitted `1000` — a number from nowhere.

1. **Adjudicator node** (gpt-5.4) operating on Plan B's candidate ledger (verbatim values +
   evidence quotes + method), ranking by explicit rules instead of fluency:
   - (a) **constraint compliance** with the question text ("using Splunk commands only",
     "first ... by Splunk event order") — kills Q331, Q212-class losses;
   - (b) **field-value fidelity** — the submitted string must be a byte-exact ledger entry,
     never a re-typed or trimmed variant (Q215 FQDN, Q221 `nullweb_admin`, Q315 filename);
   - (c) **cardinality/shape match** against `answer_guidance` ("at least two ... short
     hostnames" → the minimal consistent set, not the superset — Q323);
   - (d) **evidence strength ordering**: direct measurement > inference, sustained behaviour >
     single connection (Q210: BSTOLL-L's sustained CPU vs FYODOR-L's one pool connection),
     solved > partial (Q318).
   - On disagreement between candidates: **one targeted tiebreak query**, not a fluency pick.
   - Hard rule inherited from run_1.2's Q321: if the ledger has no candidate satisfying the
     question, submit the best honest candidate or UNKNOWN — never a synthesized number.
2. **Dual-track solve** for 1000-pt questions: planner produces two *orthogonal* plans
   (different sourcetype families / approaches); both run in parallel (pool already sized
   for 6). run_1.2 added Q330 to the evidence: the single track pre-filtered to 3 VPN users
   and ranked `bstoll` top; an orthogonal track running an unfiltered
   `stats sum(bytes) by Username` enumerates `mkraeusen` immediately.
3. **Model escalation ladder**: track A = GLM-5.2 (cheap); if adjudicator confidence <
   threshold on a 1000-pt question, rerun track B with gpt-5.4 Senior (v1.0's Senior model —
   which got Q317/Q330 right). Unchanged, still justified: the 1000-pt residue (Q216, Q217,
   Q224, Q328, Q329, Q330, Q331 — 7,000 pts) survived two full runs on cheap Seniors.
4. **Self-consistency arithmetic**: Metrics questions sampled 3× (temperature 0.3), majority
   value wins; formula must be SPL-native per C1(a). (Q206's 2.9348→2.94 rounding slip and
   Q331's method split are both caught by a 3-sample majority.)
5. **Prerequisite — fix the verifier plumbing first**: run_1.2's verifier emitted
   `verifier_failed` on 23 of 56 questions (including 10 ultimately-correct ones) because its
   `max_iter=8` cap never reached the graph's build-time step limit (15) — every run past 8
   steps was mislabeled FAILED. It corrected zero answers all run. The pending code-review
   Task 1 fix (dedicated verifier graph built with `max_iter=VERIFIER_MAX_ITER`) lands before
   any Plan C work; the adjudicator then *replaces* the verifier for candidate selection, and
   the verifier's only remaining job is confirm/refute of the single chosen answer.

**Cost impact**: adjudication runs on the ledger digest (KB, not MB) — negligible vs Senior
cost; dual-track ~2× Senior spend on the 7 remaining 1000-pt questions only. With B's handoff
savings, projected total well under run_1.2's $31.36.
**Expected recovery**: SELECTION 5,100 direct + dual-track/escalation share of the 1000-pt
search residue → ceiling **44–48/56**.

## Recommendation & sequencing

1. **v1.2 = Plan A + B1/B2/B4** (grounded joiner, verifier, cap discipline, raw-content path,
   answer-shape contract, web tool, points-aware budget, case file, recon pass, hints).
   A alone is cheap insurance; B's case file is what turns 56 isolated solves into one
   investigation. Target: **38–44/56**.
2. **Prerequisites before the run** (non-negotiable): fix the `ext["valid"]` NameError at
   `run_all_v1.py:262` (crashes on Q1 today); root-cause the ~30-min periodic process kills
   (move `log/` + checkpoint DB out of OneDrive-synced path or exclude from sync); persist
   per-delegation results so a resume continues the in-flight question instead of restarting it.
3. **v1.3 = Plan C** if the 1000-pt residue survives v1.2.
