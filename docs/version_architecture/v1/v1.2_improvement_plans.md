Cross-cutting facts:

- **Uniform effort regardless of stakes**: 46/56 questions got exactly 3 delegations. 1000-pt
  questions received the same budget as 100-pt ones. Five of eight 1000-pt questions were wrong.
- **Status labels lie**: delegations marked `solved` whose transcript ends mid-tool-call with no
  answer (confirmed on Q330). The ESCALATE→`too_big` path never fired once in 173 delegations.
- **7 crash/resume events at ~30-min intervals** (18:58, 20:08, 20:37, 21:07, 21:37, 22:07,
  22:37) each restarted the in-flight question from a blank plan. The regular cadence suggests an
  external periodic killer (OneDrive sync lock on the log dir / power policy), not code failure —
  must be root-caused before the next full run.
- **97 official hints (`ctf_hints.csv`) are completely unused.** Hint cost is 10–25 pts against
  100–1000-pt questions. A wrong answer scores 0; a hint-assisted correct answer scores 75–990.
  Expected value strongly favors buying hints when confidence is low.

## Plan A — Grounded Verification Pipeline (recommended core, lowest risk)

**Thesis**: v1.1's cheapest, most certain wins are the ~3,600 pts lost *after* the correct value
was already in hand or reachable (JOINER 2,300 + REASONING 800 + EXTRACTOR 500). Fix the pipeline
so evidence cannot be dropped, mangled, or fabricated between the worker and the scoreboard.

### A1. Evidence-grounded Joiner (anti-fabrication contract)
- Joiner prompt rewritten: `FINAL ANSWER` must be accompanied by
  `EVIDENCE: task=<n> quote="<verbatim substring from that task's result>"`.
- Deterministic guard in `joiner_node`: if the final answer string does not appear verbatim
  (case-insensitive) in any task result or the question text, the answer is tagged
  `ungrounded=true` → forces one replan round; if still ungrounded, the joiner must fall back to
  the best PARTIAL candidate quoted verbatim rather than a free-form synthesis.
- Explicit rule: "If the final delegation failed/empty, you MUST NOT invent a value. Choose the
  best evidence-backed candidate from earlier tasks or answer UNKNOWN."
- Directly targets Q211, Q221, Q225, Q303, Q312, Q331, Q333 (transcription slips like
  1367.875→1369.875 become impossible: value is copied, not re-typed).

### A2. Verifier role (new, cheap)
- New node between Joiner and Extractor: a GLM-5.2 worker in "verify mode" receives
  {question, candidate answer, evidence SPL} and runs ≤3 confirmation queries with one job:
  *prove or refute*. Refuted → one targeted replan with the refutation attached.
- Catches the SENIOR-REASONING class: wrong-timestamp "first" (Q212), unconfirmed-mining verdict
  (Q210 — which also would have prevented the Q216 cascade), literal-"None" group (Q308).
- Budget-gated: only runs for questions ≥ 500 pts (see A6).

### A3. Iteration-cap discipline + raw-content path
- When a Senior hits `MAX_ITER`, the forced final message must emit
  `PARTIAL ANSWER + evidence collected so far` — never a bare guess (Q328, Q332, Q333).
- New tool `get_raw_events(sourcetype, filter, limit≤20)` exempt from the aggregation-only verify
  rule, for content questions (email bodies, scripts, HTTP payloads): Q306, Q310, Q315, Q321, Q322.
  The verify gate keeps rejecting unaggregated `run_splunk_search`, so the exemption is explicit
  and bounded.
- Prompt patch on noise-filtering: "Never exclude processes/files by a benign-looking-name
  blocklist; suspicion comes from behavior, not names" (Q317 excluded `HxTsr.exe` by regex).

### A4. Answer-shape contract (planner → extractor)
- Planner derives an explicit `EXPECTED SHAPE` from `answer_guidance` at plan time (e.g. "bare
  model number, no vendor/suffix", "comma-separated lowercase list, no spaces").
- Extractor receives the shape + a deterministic post-pass: lowercase-compare is the scoreboard's
  own rule (`lower().strip()`), so casing never matters, but list ordering/spacing and suffix
  stripping do. Fixes Q202-class near-misses.

### A5. Web-knowledge tool
- One `web_lookup(query)` tool (Tavily or plain DuckDuckGo HTML fetch) exposed to Senior workers
  and the Verifier. Targets Q213, Q302 directly (200 pts, otherwise unsolvable) and materially
  helps CVE mapping on Q332/Q333 (2,000 pts) — "SuiteCRM RCE 2018" or "Ubuntu 16.04.4 kernel
  privilege escalation eBPF CVE" are one search away.

### A6. Points-aware budget
- ≥500 pts: MAX_ITER 15→25 per Senior, Verifier enabled, replan rounds 3→4.
- 100 pts: current budget.
- Rationale: 46/56 questions got identical effort in v1.1; the eight 1000-pt questions carry
  8,000 of 22,900 available points.

### A7. Truthful status classification
- `solved` only if a `FINAL ANSWER:` tag exists; empty/mid-stream transcript → `failed`;
  cap-hit → `partial` + `cap_hit=true`. (v1.1's 70% "solved" rate is inflated.)

**Cost impact**: +1 verifier call and occasional +1 replan on ~25 high-value questions, still on
GLM pricing. Est. total run cost $0.9–1.2 (vs $0.63).
**Expected recovery**: JOINER 2,300 + REASONING 800 + EXTRACTOR 500 + KNOWLEDGE 200 + partial
SENIOR-SEARCH (content path + cap discipline ≈ 1,500–2,500) → **realistic target 34–38/56,
~12,000–13,500 pts.**

## Plan B — Case-File Blackboard + Recon Pass + Specialist Workers (bigger redesign, highest leverage on remaining search failures)

**Thesis**: BOTSv3 is *one coherent incident*; the 56 questions are probes into a single attack
narrative. v1.1 rediscovers the incident from scratch 56 times through a lossy chat-history
memory that also propagates unverified errors. Replace the memory with a structured, confidence-
tagged case file, and build the narrative once up front.

### B1. Structured case file (replaces raw chat-thread memory as planning context)
- SQLite/JSON store: `entities` (hosts, users, IPs, domains, files, hashes, buckets, CVEs),
  `findings` (claim, evidence SPL, source qid, **status: verified | hypothesis | refuted**,
  confidence), `attack_timeline` rows.
- SH planner prompt gets a rendered case-file digest instead of (or alongside a truncated) raw
  message history. LangSmith shows SH context ballooning to 200–320K tokens per question by run
  end — the case file caps planner context and kills the contamination channel.
- **Cascade killer**: carried-forward claims arrive labeled `hypothesis` until a Verifier (A2)
  promotes them. Q210's wrong FYODOR-L verdict enters as hypothesis → Q216's plan is required to
  re-verify before scoping to it. Q310→Q311/Q312 same.
- Writes: Joiner emits `CASE UPDATES:` block (structured lines) parsed into the store.

### B2. Phase-0 recon pass (run once, before the question loop)
- 4–6 parallel Senior workers build the incident skeleton: sourcetype inventory with event-count
  time ranges, key hosts + roles, the phishing waves, C2 infrastructure, cloud story. Written into
  the case file as verified baseline (~10 min wall, ~$0.10).
- Fixes PLAN-misdirection (Q329: recon knows the malicious doc exists and where; the plan
  inspects its content instead of chasing a literal string) and wave-confusion (Q310: recon
  distinguishes phishing wave 1 vs 2).

### B3. Specialist worker types (same v0 graph, different prompt + tool config; router = one line in planner output)
| Specialist | Config delta | Target questions |
|---|---|---|
| **Hunter** (default) | current Senior | entity/pivot questions |
| **Content-Inspector** | `get_raw_events` allowed, aggregation gate relaxed, prompt tuned to read bodies/scripts/URIs | Q306, Q310, Q315, Q321, Q322 class |
| **Metrics-Analyst** | prompt mandates SPL `eval`-based arithmetic + a `python_calc` tool for cross-checking; must show formula and inputs | Q206, Q211, Q224, Q331 class |
- Planner tags each task `[HUNTER]` / `[CONTENT]` / `[METRICS]`; executor picks the graph.

### B4. Hint economy
- `ScoreboardClient`/`LocalScoreboard` extended: `buy_hint(number)` deducts `HintCost` from that
  question's earned points (honest scoring, matches official CTF rules).
- Policy: Joiner/Verifier confidence low after round 2 **and** points ≥ 500 → buy hint 1, replan
  with it. 97 hints exist; hint 1 is typically the sourcetype pointer — exactly what
  SENIOR-SEARCH failures were missing.

**Cost impact**: recon ~$0.10; case-file rendering *reduces* SH input tokens; hints cost points
not dollars. Est. $1.0–1.4/run.
**Expected recovery**: on top of Plan A, attacks the residual SENIOR-SEARCH block (8,300) via
recon + specialists + hints, and MEMORY (1,500) + PLAN (1,000) structurally →
**realistic target 40–45/56, ~15,000–17,500 pts.**

## Plan C — Adversarial Dual-Track + Escalation (highest ceiling, most cost; hold for v1.3 unless A+B plateaus)

**Thesis**: for the hard residue (1000-pt search questions), a single investigation line anchors
on its first hypothesis (Q208 hard-coded `MicrosoftEdgeCP#2` into its own verification SPL).
Independent tracks + adjudication beat single-track depth.

1. **Dual-track solve** for ≥500-pt questions: planner produces two *orthogonal* plans (different
   sourcetype families / approaches); both run in parallel (pool already sized for 6).
   An **Adjudicator** (gpt-5.4) compares evidence, and on disagreement issues targeted tiebreak
   queries rather than picking by fluency.
2. **Model escalation ladder**: track A = GLM-5.2 (cheap); if adjudicator confidence < threshold
   on a 1000-pt question, rerun track B with gpt-5.4 Senior (v1.0's Senior model — which got
   Q317/Q330 right).
3. **Self-consistency arithmetic**: Metrics questions sampled 3× (temperature 0.3), majority
   value wins, Verifier confirms formula.
4. Keeps A1's grounding contract — adjudicator must also cite verbatim evidence.

**Cost impact**: ~2–2.5× v1.1 → $1.5–2.5/run (still 3–5× cheaper than v1.0's $7.36).
**Expected recovery**: +2–4 questions among the 1000-pt residue (Q329, Q330, Q332, Q333, Q328) —
each worth 1,000. Ceiling **45–48/56**.

## Recommendation & sequencing

1. **v1.2 = Plan A + B1/B2/B4** (grounded joiner, verifier, cap discipline, raw-content path,
   answer-shape contract, web tool, points-aware budget, case file, recon pass, hints).
   A alone is cheap insurance; B's case file is what turns 56 isolated solves into one
   investigation. Target: **38–44/56**.
2. **Prerequisites before the run** (non-negotiable): fix the `ext["valid"]` NameError at
   `run_all_v1.py:262` (crashes on Q1 today); root-cause the ~30-min periodic process kills
   (move `log/` + checkpoint DB out of OneDrive-synced path or exclude from sync); persist
   per-delegation results so a resume continues the in-flight question instead of restarting it.
3. **v1.3 = Plan C** if the 1000-pt residue survives v1.2.
