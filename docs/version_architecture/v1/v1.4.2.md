# v1.4.2 — routing the second opinion

**Status:** in progress. Started 2026-09-20, after v1.4.1's smoke round closed 2/5
(`v1.4.1.md`, "v1.4.1 smoke test results" and "Round conclusion").

v1.4.1 proved the loop can produce a second opinion. It lost all three hard questions on
what SH did with one: it briefed alternatives by "don't overlap the last senior" instead of
"where the evidence of the act lives", and threw away an entity a second senior had proved
because it came from another feed. v1.4.2 is about that routing decision, plus the four
runner defects the round exposed.

## Changelog

- **Iterations per round: 12 -> 10** (`question_state.ROUND_ITERS`); rounds per senior stay
  at the 1000-tier's 8 (a brief raise to 10 was reverted the same day). A shorter round hands
  control back to SH more often, so a wrong path is caught sooner. Cut-off rounds are
  EXPECTED and are not a defect: at the cap the graph withdraws the search tools and asks
  for a final `submit_finding`, so the round ends on a forced summary of completed work, not
  mid-search. The iteration ceiling becomes 3 x 8 x 10 = 240.
- **Per-reply output budget: 32768 -> 65536** (`splunk_agent.token_limit_kwargs`). Probed
  against AI& on 2026-09-20: it accepts both 65536 and 131072 for `zai-org/glm-5.3`. GLM-5.3
  is a reasoning model and its hidden chain-of-thought is billed and capped as output, so
  two smoke3_r2 rounds returned `finish_reason=length` at exactly 32768 output tokens with
  no text and no tool call — the whole budget went on thinking and the round reached SH
  blank. Successful calls emit 47-2,667 tokens, so this is headroom, not a working budget;
  runaway generation is still bounded per round by `round_output_cap`.
- **Retire a dead direction immediately** (SH prompt, ALTERNATIVE SENIOR). RETIRE + SPAWN in
  the same turn as soon as the senior's OWN report shows its constraints cannot hold the
  answer (no such field, no content, no coverage). A round spent establishing that is a
  round well spent — what must not follow it is another round inside the same dead scope.
  The other two triggers (a candidate still UNVERIFIED after a verifying round; the same
  narrowed lead unsettled) stay.
- **Brief the replacement on the deviation.** The new direction must not re-walk the retired
  path: name fields, feeds or entities it did not touch, say where evidence of the ACT would
  sit if the first reading was wrong, and say what to avoid. A deviation may be small — the
  same feed through a different field counts; the same field again does not. The candidate
  is never handed over for confirmation, but any ENTITY the retired senior established is:
  "carrying a proven entity into the feed the question names is the most common way a stuck
  question is solved; dropping it because it was found elsewhere is how one is lost."
  (Q216: s2 proved the Coinhive host, SH discarded it as another feed's finding.)
- **R1 is about contribution, not about answering** (`SeniorDirective.r1_scope_alignment`
  description and the SH prompt's R1 walk). PASS = this round moved the identification of
  an entity the answer depends on, including from an angle SH did not ask for, or ruled one
  out with evidence. FAIL is reserved for work that cannot bear on the question. The
  word-by-word walk (entity / act / measure / reach) now grades the CHAIN AN ANSWER RESTS
  ON, via the premise audit, instead of sinking the round's grade. Leak-free general rule
  added in the same place: "an entity a senior found in another feed is a LEAD to test in
  the feed the question names — the question's wording binds where the MEASUREMENT is taken,
  not where the entity may be recognised."
- **A CLARIFY reply now really clears the cut-off block** (`QuestionState.clear_cap`, called
  from the loop's CLARIFY branch). The gate's message already offered CLARIFY as the cheap
  remedy but nothing cleared the flag, so Q216 spent ~5 turns clarifying into a gate that
  could not open. Message reworded to say the reply clears it.
- **Quotes may come from a CLARIFY reply** (`sh_loop` keeps `clarify_text` per senior and
  feeds it to `evidence_violations.reports_of`). SH was told to quote the senior word for
  word, then had its quotes rejected because the senior had said it in a clarify.
- **A question no longer ends with a CLARIFY reply unread** (`unread_clarify` joins `unread`
  in the loop's budget check). Q329 ended the instant s3 replied, so SH never read it.
- **An empty round says so** (`SeniorSession._fallback_report`). A senior that skips both
  `report` and `notes` used to reach SH with a blank "What it means" (Q329 s1 r2-r3). The
  fallback now uses `evidence`, then `answer`, and otherwise states plainly that nothing was
  filed.
- Tests: tier table, ceiling and token-cap expectations updated; suite 496 passed, 5 skipped.

## Root causes recorded for the v1.4.1 defects

- **Cut-off (`cap_hit`)**: `splunk_subagent` sets it when `step_count > max_iter`. At the
  cap the graph withdraws the search tools and asks for a final `submit_finding`, so the
  round ends on a forced summary rather than mid-search. The report is therefore honest but
  incomplete, which is why the ANSWER gate blocks on it.
- **Empty rounds**: `finish_reason=length` with `output_tokens=32768` in
  `log/temp/_smoke3_r2.out` — the senior's reasoning consumed the whole output budget and
  returned no text and no tool call. The agent node already retries once for
  `submit_finding`; what was missing was a readable report when that retry returns a finding
  with no `report` and no `notes`.
