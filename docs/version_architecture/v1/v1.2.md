# SIEM Agent v1.2 — Persistence + Extractor Simplification

> **Code**: `agent/v1/`
> **Predecessor**: [v1.1](v1.1.md) — LLMCompiler SH + parallel Senior workers + GLM-5.2 + token tracking.
> **Status**: In progress — no full `run_all_v1.py` run yet. This doc is a running changelog;
> every change lands here as it's made, and gets folded into a "What changed vs v1.1" summary
> once the version is closed out by its first full run.

## Changelog

- **SQLite-backed cross-question memory (`SqliteSaver`)**. v1.1's SH used LangGraph's
  `MemorySaver`, which lives only in process RAM — every time the runner process was killed and
  resumed (external kills happened repeatedly during the v1.1 full run), the SH's entire
  cross-question memory thread was silently wiped, and the next question's planner started from
  a blank slate instead of seeing prior questions' plans/findings/answers. Fixed by swapping to
  `langgraph_checkpoint_sqlite.SqliteSaver`, writing checkpoints to
  `<run_dir>/sh_checkpoints.sqlite`. `build_sh_agent_compiler()` now takes an optional
  `checkpoint_db_path`; when set, checkpoints persist to disk and survive process restarts.
  Verified with a real two-process test: process 2's SH plan explicitly referenced process 1's
  prior answer after a full process restart.

- **`run_summary.json` resume-merge**. Previously a resumed run (`--start Qxxx --run-name
  <name>`) overwrote `run_summary.json` with only the new segment's data, losing the prior
  segment's results, score, and token/cost totals from view (the scoreboard's own
  `scoreboard_submissions.json` was still cumulative and remained the source of truth, but the
  summary file misrepresented the run). `run_all_v1.py` now loads the existing
  `run_summary.json` at startup if present and seeds `results`, `score`, `total`,
  `failed_delegations`, and token/cost counters from it; new questions append instead of
  replacing. Added `UsageTracker.seed()` to pre-load token/cost counters from a prior segment's
  saved totals (recomputing cost from raw token counts rather than trusting the old dollar
  figure, so a stale price table at seed time doesn't propagate forward). Also fixed a latent
  bug in `UsageTracker.totals()` where the `combined` per-model dict was built via a naive
  `{**self._models, **self._nim}` spread that silently clobbered overlapping model keys instead
  of summing them — not reachable until seeding made overlaps possible. Verified end-to-end with
  two separate process launches sharing one `--run-name`: final `run_summary.json` showed both
  questions merged, additive score, and additive token/cost totals.

- **Remove extractor validation node.** The Extractor no longer validates the SH's answer
  against the question's format guidance or asks the SH to retry on rejection — it only strips
  prose down to the bare answer now (`Extractor.extract()`; `validate()` and `process()` are
  gone). `run_all_v1.py`'s per-question loop calls `extractor.extract()` once and submits
  directly; the `EXTRACTOR_MAX_RETRIES` retry loop, `extractor_rejections` counter (console
  output, timeline, `run_summary.json`), and the `_NON_ANSWER` regex are all removed.

- **Bug-hunt sweep (2026-07-07): 18 findings from a 3-reviewer parallel audit, all fixed.**
  Findings were adversarially verified against source before fixing. The ones affecting the
  v1 pipeline's correctness:
  - `run_all_v1.py`: removed leftover `ext["valid"]`/`ext["reason"]` result fields — `ext` was
    undefined since the extractor simplification, so every question crashed with `NameError`
    right after scoreboard submission (run could never get past its first question).
  - `run_all_v1.py`: resume hardening — `--start` on a full run now *requires* `--run-name`
    (previously it silently allocated the next `run_1.x` dir, stranding the prior segment and
    resetting SH memory), and resumed runs skip questions already recorded in
    `run_summary.json` instead of re-running them and double-counting `total`/`score`.
  - `orchestrator.py`: `parse_plan` regex now tolerates leading whitespace (`^\s*(\d+)\.`) —
    the joiner's own REPLAN template indents tasks by two spaces, so a templated replan parsed
    to zero tasks and fell through to the last-line fallback, submitting a replan task sentence
    as the final answer. Also: `$N` deps are filtered to real task indices (a literal "$40" in
    a subquestion no longer creates a phantom dependency), and `substitute_deps` leaves
    non-task `$N` text untouched.
  - `local_scoreboard.py`: `submit()` now replaces any prior record for the same question
    number — resumed runs re-submitting a question no longer double-count points in
    `get_score()`/`scoreboard_submissions.json`.
  - `usage_tracker.py`: `seed()` now trusts the stored dollar figure instead of recomputing
    from aggregate token counts — the recompute applied gpt-5.4's ≥272k long-context tier to a
    whole segment's input as if it were one call, roughly doubling resumed-run cost, and made
    `__sh_cumulative__` disagree with the per-model row.
  - `agent_logger.py`: worker counters seed from the existing `timeline.md` in append mode, so
    resumed runs continue `Senior #N` numbering instead of reissuing duplicate labels.

  Shared-infra fixes that also affect v1 runs:
  - `splunk_agent.py`: `_format_result` truncates by dropping whole result rows (payload stays
    valid JSON; the old byte-slice broke the model's evidence *and* the error/empty dedup
    guard); the field manifest is written atomically (tmp+rename) under a `threading.Lock`
    (parallel Senior workers raced the read-modify-write); the verify gate accepts
    `sourcetype IN (...)` (the system prompt recommends IN, the gate rejected it); model-supplied
    keywords are stripped of `"`/`|` before SPL interpolation.
  - `splunk_client.py`: search polling gained `raise_for_status()` (mid-search 401s now surface
    as `HTTPError` so the pool's re-auth retry can fire, instead of `KeyError` crashing the
    worker) and a 600s deadline (a stuck QUEUED job no longer holds a pool slot forever);
    generating-command detection now covers any leading `|`; keyword/field/sourcetype args
    sanitized.
  - `build_manifest.py`: atomic manifest write (a mid-write kill left a truncated
    `botsv3_fields.json` that broke every subsequent run).

  Legacy (v0) runner + scoreboard fixes, same sweep:
  - `run_all.py`: `create_agent` now receives `model=MODEL` explicitly (defaults bind at import,
    so the temp runners' `run_all.MODEL` patches were silently ignored — `run_gpt5mini_temp.py`
    was actually running full gpt-5.4); the extractor call is wrapped (one NIM 504 killed the
    run after the agent answer was already paid for); final summary guards `get_score()` and
    division-by-zero; `Tee` warns once when log-file writes start failing.
  - `run_nemotron_ultra.py` / `run_gpt5mini_temp.py` / `run_gpt5_temp.py` / `run_single.py`:
    removed dead `agent_mod.MODEL`/`NIM_*` monkey-patches; model + base_url now passed as real
    kwargs (the nemotron runner would have hit api.openai.com with a NIM key → 401 on all 58
    questions while labeling results "kimi-k2.6").
  - `run_gpt54mini_native.py` / `run_nemotron_ultra.py`: fixed-filename results/logs are now
    resume-safe — prior JSON results preload (resume appends, skips done ids) and the log opens
    in append mode (previously a `--start` resume truncated the log and rewrote the JSON with
    only the resumed segment, destroying all earlier results).
  - `scoreboard_client.py` (Windows scoreboard path): `_log_submission` no longer swallows
    failures (that event *is* the scoring record `get_score()` sums) — it retries once with a
    fresh token then raises; `_kv_get_all` re-auths on 401 (session TTL expired mid-run);
    `get_score()` dedups by question `Number` (test-script and resume re-submissions inflated
    cumulative points); `get_all_submissions()` SPL had literal `\"` escapes that matched
    nothing — rewritten rex-style like `get_score()`; submitted answers sanitized before being
    embedded in the event line.
  - `setup_scoreboard.py`: a partial KV-store load (delete-then-insert with per-row failures
    only printed) now exits fatally instead of ending "Setup complete" — missing `ctf_answers`
    rows silently scored correct submissions as wrong forever.
  - `mcp_bridge.py`: error responses keep the request id (clients no longer hang pending
    requests on bridge errors); JSON-RPC notifications no longer receive replies.

  Verified: `py_compile` on all 17 touched files plus behavior tests for `parse_plan`
  (indented REPLAN, `$40` dep filtering), `_format_result` (oversized + single-huge-row payloads
  stay valid JSON), the verify gate (`IN`/`=`/missing sourcetype), `LocalScoreboard` resubmit
  dedupe across a simulated resume, and `UsageTracker.seed()` cost preservation.
