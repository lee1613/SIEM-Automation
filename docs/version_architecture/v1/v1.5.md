# v1.5 — the premise ledger

**In progress.** Spec: `docs/superpowers/specs/2026-09-20-premise-ledger-design.md`.
Plan: `docs/superpowers/plans/2026-09-20-premise-ledger.md`.

v1.5 replaces the senior's prose `## Assumptions` section, and the five regexes that
read it, with one runner-owned structured premise ledger. The root cause it targets is
v1.4.2's Q216 loss: a premise cannot be laundered out of existence by writing a
cleaner report next round, because the senior never re-emits the list.

## Changelog

- **Probed GLM-5.3 on AI& for nested tool arguments (2026-09-20).** `submit_finding`
  took only flat primitives, and the whole ledger design depends on the senior being
  able to emit a list of objects. A one-off probe bound a tool with
  `new_premises: list[dict]` and `open_questions: list[str]` to `zai-org/glm-5.3` at
  `https://api.aiand.com/v1` and asked for two premises and one question.

  Result: **nested objects work.** The model returned
  `[{'kind': 'other', 'load_bearing': True, 'text': 'The flow is inbound-heavy.'},
  {'kind': 'definition', 'load_bearing': False, 'text': 'Port 3333 alone does not
  prove the activity.'}]` — every field present, both kinds correct, both booleans
  correct — and `open_questions` as a plain list of strings.

  So `submit_finding` types `new_premises` and `premise_updates` as `list`, and the
  JSON-string fallback in spec §5 is not needed. `finding._coerce_objects` still
  accepts a JSON string as cheap insurance against a provider changing its mind.

  (The probe first failed with `model_not_found` against `glm-5.3`: the id on AI& is
  `zai-org/glm-5.3`, as `run_all_v1.SENIOR_MODEL` already had it.)

- **`agent/v1/premise.py` — new (Tasks 1-5, `fe42a4f`..`ecdf6fb`).** The ledger:
  `PremiseDraft` / `PremiseUpdate` / `Premise` / `OpenQuestion`, `PremiseLedger`
  (filing, reading, transitions, rendering, `to_records`) and `dump_ledgers`. Ids are
  assigned by the runner and are global to the question, because a premise filed by
  one senior may be settled by another. `text` is immutable once filed. REFUTED is
  terminal. 30 tests.

- **Review fixes on the ledger (`67a0f1d`).** A code review of the above found four
  defects worth recording:

  1. **The quote check could not match a real quote.** `quote_supported` normalised
     with a markdown-only `_norm`, but a senior's tool output is JSON
     (`splunk_agent._format_result` returns `json.dumps({"results": ..., "meta": ...})`),
     so the corpus holds `{"dest_port": "3333"}` while a senior restates it as
     `dest_port=3333`. Nothing would have matched, every honest VERIFIED would have
     been rejected, and every answer would have deadlocked — v1.5 would have scored
     *worse* than v1.4.2 and looked like a model failure rather than a string-matching
     bug. Replaced by `_match_form`, which compares alphanumeric runs and ignores the
     punctuation between them; the 12-char floor is applied after normalisation so
     padding cannot buy length.
  2. **The carry-forward block ordered the impossible.** It listed every premise that
     was not VERIFIED, which includes REFUTED, and told the senior to settle each —
     but `apply()` refuses any update to a REFUTED premise. Now lists UNVERIFIED only;
     refuted premises are `render_refuted()`'s job.
  3. **Duplicates accumulated forever.** `add()` did not dedupe, and the carry-forward
     block actively invites re-filing. Settling one copy left its twin open for the
     rest of the question. `add()` now returns the existing premise for the same
     author and the same `_match_form(text)`.
  4. **VERIFIED was accepted with empty `evidence`** — the quote got a provenance
     check and a rejection note while the field that connects the quote to the premise
     got nothing. Now rejected with a note.

  Also deleted `blocking()` (dead, and its docstring falsely claimed it gates an
  ANSWER) and the unused `STATUSES` constant, and added tests for the forensic
  invariant that a *rejected* update must not append to `history`.

- **`premise._norm` deleted (`1b457ee`).** Left without a caller once `_match_form`
  took over, and `conversation.py`'s three uses are its own local copy inside
  `evidence_violations`, which a later task removes. It was alive only through its own
  test — the pattern the review flagged for `blocking()`.

- **`agent/v1/finding.py` — `submit_finding` files premises (Task 6, `dbf0e0f`).**
  Three new parameters (`new_premises`, `premise_updates`, `open_questions`) and their
  parsing in `parse_finding`, with `empty_finding` carrying the same keys so the
  prose-fallback shape stays identical to the structured one. `_coerce_objects`
  accepts a real list or a JSON string, so a provider that flattens nested arguments
  costs nothing. A malformed draft is dropped rather than fatal; an illegal status is
  dropped, leaving the premise at its old status, which is the safe direction.

  **Verified end to end against the live provider**, not just in unit tests: the
  generated schema for `new_premises` is
  `{"default": null, "items": {}, "title": "New Premises", "type": "array"}`, and
  `zai-org/glm-5.3` fills it with well-formed objects (correct `kind`, correct
  `load_bearing` booleans) which `parse_finding` turns into `PremiseDraft`s. This
  matters because Task 0 probed a *required* `list[dict]` while the real tool declares
  an *optional* `list` with a null default — a different schema, and the assumption
  was worth testing rather than inferring.

- **`agent/v1/conversation.py` + `agent/v1/sh_loop.py` — SH's half of the ledger
  (Tasks 8 and 9).** Done as one change: Task 8 deletes symbols `sh_loop.py` uses
  until Task 9, so splitting them leaves the suite red in between.

  `AuditLine`, `premise_audit`, `_audit_from_text`, the local `_norm`/`MIN_QUOTE_CHARS`,
  `unverified_audit` and `evidence_violations` are gone. `SeniorDirective` now carries
  `new_premises`, `premise_updates` and `answer_premise_ids` — SH writes into the same
  ledger as its seniors, as `author="sh"` — and `open_question_answers` is a list of
  `QuestionAnswer` (id + answer) instead of a bare list matched by index, which is how
  SH could answer question 2 twice and pass a count check.

  Four gates read the ledger now: `premise_audit_violations(entries, ledger)` (an
  ANSWER must cite existing ids, one of them `coverage`), `ledger_violations` (a
  load-bearing UNVERIFIED premise blocks while `unsure_remedy` has something to
  offer; a REFUTED one blocks with no escape at all), `sh_update_violations` (a
  VERIFIED/REFUTED verdict must quote a senior's report word for word via
  `quote_supported`, and may not cite SH), and `open_question_violations(entries,
  ledger)` matching by id. The `unverified_audit` block in `directive_violations` is
  deleted; the cut-off gate beside it is untouched.

  In `sh_loop.py`: one `PremiseLedger` per question, passed to every `SeniorSession`
  and returned as `run_question()["ledger"]`. The `doubts` dict and `carry_doubts` are
  gone — a premise that is not VERIFIED is the same thing, and the ledger already
  carries it forward. `render_wave` prints `render_table()` in place of the three
  regex `!!` warnings (unverified count, missing Coverage, missing Selection); absence
  of a `coverage` row is the warning. `_directive_text` no longer prepends a
  verify-first reminder on a WEAK/FAIL R4: `SeniorSession._message_for` prepends the
  senior's unresolved premises to *every* round, unconditionally, and the old prefix
  fired on SH's own grade — which is all-PASS whenever SH wants to answer.

  SH's ledger writes land only on a turn that passed every gate (after the
  `problems`/`continue` block). Consequence worth knowing: SH cannot file a premise
  and cite it in the same ANSWER turn — the citation is checked before the filing
  happens, so that turn is rejected and its writes discarded. SH has to file on an
  earlier (non-ANSWER) turn, or cite what a senior filed. That is the intended
  trade-off — nothing written from an invalid turn — but it costs a turn the first
  time SH discovers it.

  Prompts rewritten to match on both sides: SH's `AUDIT THE CHAIN` paragraph becomes
  `THE PREMISE LEDGER` plus the trace-and-file instruction; the gate bullets name the
  ledger, the UNVERIFIED block and the REFUTED no-escape block. `SENIOR_BRIEF` loses
  the `## Assumptions` and `## Open questions for SH` report sections (`## Ruled out`
  is now the template's last), and every prose reference to "your Assumptions" is
  re-pointed at `new_premises` / `premise_updates` / `open_questions`.

  Tests: `agent/v1/tests/` goes 563 -> 574 passing. Converted rather than dropped —
  each encodes a real failure from a past run — except four whose only subject was the
  legacy `"<premise> - VERIFIED: <where>"` string parsing or the `!!` regex warnings,
  which are superseded by the ledger tests.
