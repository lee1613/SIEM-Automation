## Changelog

- Task 1: Verifier now gets a dedicated pre-built graph (`SplunkWorkerPool.verifier_graph`,
  `max_iter=VERIFIER_MAX_ITER=8` baked in at build time) instead of being routed to
  `senior_graph` (real cap 15) with a mismatched `max_iter` argument that never reached
  LangGraph's build-time step-cap closure. `VERIFIER_MAX_ITER` moved from `orchestrator.py`
  to `splunk_subagent.py`.
- Task 2: `build_metrics_row`'s `grounded` field now reuses `grounding.is_grounded`
  (component-wise comma-list matching) instead of a stale naive whole-string copy that
  reported every correct list answer as ungrounded.
- Task 3: `joiner_node`'s grounding-forced-replan branch no longer increments `plan_round`
  itself (it routed to `planner_node`, which independently did its own +1) — one grounding
  failure was burning 2 of the 3 allowed replan rounds.
- Task 4: `is_grounded` now checks the whole answer string as a substring before falling
  back to comma-split component matching, and refuses to treat all-digit comma parts as a
  list (thousands-separated numbers) — fixes a vacuous-grounding gap where a fabricated
  composite number like `"1,234"` could ground on unrelated stray digits ("1", "234")
  appearing elsewhere in evidence. Deviated from the plan's literal Step 3 code: that
  version (whole-string-first only, no digit guard) still failed its own new test
  (`test_short_numeric_value_not_vacuously_grounded_by_stray_digit`) — verified live before
  landing the digit-guard addition.
- Task 5: `joiner_node`'s FINAL ANSWER grounding check now merges `ctx.q_delegations`
  (every delegation this question has produced across all rounds) into the evidence dict
  passed to `decide_joiner_answer`, not just the current round's `task_results` (which
  resets to `{}` on every REPLAN) — a correct value proven in an earlier round and restated
  later was previously rejected as ungrounded.
- Task 6: `make_report.py`'s `load_events`/`load_metrics` now catch `JSONDecodeError`
  (reusing `compare.py`'s defensive read pattern) instead of crashing `--watch` when a poll
  lands mid-write on `metrics.json` (full-file rewrite each question) or `events.jsonl`.
- Task 7: extractor-outage fallback (all extractor retries exhausted) now reuses
  `grounding.best_candidate(ctx.q_delegations)` instead of taking `.splitlines()[-1]` of
  `sh_answer`, which can be raw multi-line prose when `sh_answer` came from the joiner's own
  ungrounded-rounds-exhausted `best_candidate` fallback rather than a single-line FINAL
  ANSWER tag — the exact v1.2 Q200 last-line-submission bug class, reintroduced at a
  different call site.
- Task 8: `_classify` now checks `FINAL ANSWER` before `PARTIAL ANSWER` — a worker response
  containing both phrases (e.g. "No partial answer needed here — FINAL ANSWER: 42") was
  misclassified `partial` despite a firm answer being present.

**Task 1 live smoke test** (`--ids Q209`, 500pt question, `log/temp/`): scored correct
(500/500). Verifier ran within its real 8-iteration cap (`cap_hit=False` computed against
the dedicated `verifier_graph`, not the old mismatched 15-iter graph); it returned
inconclusive (`status=failed`) and, per the "never override on failure" rule, correctly kept
the joiner's already-correct answer.

All 8 findings landed; `python -m pytest agent/v1/tests/ -q` → 77 passed (baseline 66 + 11 new).
