## What changed vs v0.3.0

v0.4.0 replaces v0.3.0's plan-and-execute replan loop with a bounded conversation. In v0.3.0,
SH planned a DAG of one-shot workers, a joiner read their results, and a `REPLAN:` threw them
away and briefed fresh ones. In v0.4.0, a few question-scoped seniors keep their LangGraph
thread across rounds. Each files a templated report every 8 iterations, and SH grades it and
steers it with one of six typed routes. The senior model also changed in this cycle, from
`gpt-5.4-mini` to `zai-org/GLM-5.3` on Featherless. That was a GENERAL change made by user
decision, and it confounds the cost comparison below.

| Area | v0.3.0 (`aea134c`) | v0.4.0 |
|---|---|---|
| SH loop | Planner → executor → joiner → `REPLAN:` (`MAX_PLAN_ROUNDS`) | `sh_loop.run_question()`: SH reads a whole wave per turn, emits one route per senior |
| Worker lifetime | One-shot; a replan re-briefs replacements from zero | Question-scoped; thread resumed each round (`pool.run_round`), max 3 spawns |
| SH output | Free-text plan / `REPLAN:` parse | Strict json_schema `SHTurn`: SPAWN / RETIRE / COMMAND / CRITIC / CLARIFY / ANSWER |
| Worker output | `submit_finding` value + evidence | Same, plus `insight` (FOUND/NOT_FOUND) and a ~400-word templated `report` |
| Progress signal | None | Runner-stamped `round`, `rounds_remaining`, `novel_spl`; code FAILs R2 on `novel_spl == 0` |
| Review | Joiner prose | R1 scope / R2 progress / R3 readiness graded per senior per round, logged |
| Gates | Grounding only | Grounding + anti-thrash (2× R2 FAIL) + wrong-question (R1 FAIL) + capped-report block |
| Budget | `MAX_PLAN_ROUNDS` | Tier table on `base_points`: seniors / waves / SH turns, iteration ceiling 24/80/192 |
| Context | Unmanaged | Predictive start-of-round compaction at 80% of the provider-served window |
| Artifacts | Worker logs | Plus `conversation.md`, `reports/`, `handoffs/` per question |
| Senior model | `gpt-5.4-mini` (OpenAI) | `zai-org/GLM-5.3` (Featherless) — GENERAL |

The compiler loop still builds and runs behind `--loop compiler` for A/B.

### The four success criteria

1. **Score — met.** 2/5 against the baseline's 0/5.
2. **Cost per question — not met.** $1.29 per question against a ~$0.55 limit (2× the $0.272
   baseline). The tracker total is $6.4483, priced locally from `PRICES_PER_1M`. The provider
   figure has not been checked. The partial Q224 in `test_20260918_113209` is not included.
   The loop is not what drove the cost up. Senior input tokens actually **fell** (4.39M against
   the baseline's 5.32M), and so did iterations (criterion 3). The rise comes from the senior
   model: GLM-5.3 on Featherless bills uncached input at $1.40/M against `gpt-5.4-mini`'s $0.75.
   Its cache hit rate was 31–46%, against 88%. And as a reasoning model it produced 7.6× the
   output tokens (419k against 55k). Two unsolved questions that ran their full budget, Q217
   and Q329, account for $4.95 of the $6.45. Settling what the loop itself costs needs an
   A/B on the same senior (`--senior-model gpt-5.4-mini --senior-base-url ""`). That is a
   paid run and needs user go-ahead.
3. **Actual vs ceiling iterations — met.** Mean 36 senior iterations per question (range 9–72)
   against the baseline's 80 and a ceiling of 192. No question came near the ceiling, so
   demand-driven spawning works.
4. **Verifying, not rubber-stamping — met, with gaps.** 22 graded rounds, pooled:

   | | PASS | WEAK | FAIL |
   |---|---|---|---|
   | R1 scope | 13 | 9 | 0 |
   | R2 progress (effective) | 18 | 2 | 2 |
   | R3 readiness | 3 | 0 | 19 |

   R3 is discriminating: its three PASSes are exactly the three rounds SH answered from. SH acts
   on its own grades. It continued after 33–45% of R2-PASS rounds and never after a WEAK or FAIL,
   with zero contradictions. No round repeated its queries (`novel_spl == 0` in 0 of 22). The
   gaps: **CRITIC and CLARIFY were never used** in 22 rounds (routes issued: 13 COMMAND, 9
   SPAWN, 6 RETIRE, 3 ANSWER), and **R1 never FAILed**. So the wrong-question gate has not yet
   been exercised.

| Ends | — | answer ×3, rounds ×2 | answer ×2, turns ×1, rounds ×2 |

This settles criterion 2's confound. **The conversational loop is not what costs money.** On
the same senior it cost *less* than v0.3.0 ($1.26 against $1.36), even though SH's share rose
($0.57 against $0.29) because SH now reads every round. The 4.7× cost of the GLM run is the
senior model. **The score came from the senior model too.** The loop with mini solved nothing,
and the two correct answers appeared only with GLM-5.3. Whether GLM would also score under
v0.3.0 is untested. Latency roughly doubles on the same senior (18 → 37 min), because the loop
waits on SH between rounds instead of fanning workers out in parallel. Mini's three
"SH retired without answering" results (Q217, Q328, Q329) are the honest fallback working as
intended. Before `b65cf52`, each would have submitted whatever value a senior happened to hold.

### Findings from the transcripts

- **The fallback bypasses the wrong-question gate (Q217).** SH declined to answer and retired s2
  "rather than force an unsupported answer". The runner then hit the wave budget and logged
  `question ended: rounds — falling back to 'pwned.jpg'`. That value is a filename, submitted
  for a question that asks for a chart type. An ANSWER route would have had to pass the R1 gate.
  The end-of-budget fallback only skips values from R1 = FAIL reports (M3/M4). No Q217 report
  was graded R1 FAIL (2 PASS, 6 WEAK), so the fallback took the value. **Fixed 2026-09-18**:
  the fallback is gone and the question submits `"SH retired without answering"` (see
  [`v0.4.1.md`](v0.4.1.md)).
- **Retirement with handoff works (Q328).** s1 established the tomcat8 → `/tmp/colonel.c` chain
  from osquery, but its scope could not show file contents (R3 FAIL twice). SH retired it with a
  handoff and spawned s2 on the Struts2 HTTP delivery path, citing that gap. s2 answered in its
  first round. A v0.3.0 replan would have re-briefed from zero.
- **The rubric drove the clean case (Q224).** Round 1 was graded R3 FAIL, so SH issued a COMMAND
  to continue. Round 2 was graded R3 PASS, so SH answered. 13 iterations.
- **Q216 is on older code.** It ran before the capped-report gate (`bedd135`) and answered from
  a capped round. Its wrong answer is the evidence that motivated that gate, and the gate has not
  been re-tested on Q216 since.
- **Q329 exhausted every senior.** Three seniors across O365, endpoint, SMTP and HTTP evidence
  graded R3 FAIL in all eight rounds. No candidate reached the ledger, so nothing was submitted.

## Decisions from the smoke run

**Technique axis (§2.4, §12) — `hunter` and `content` removed from SH's SPAWN; `metrics` kept.**
Applied 2026-09-18 on the user's go-ahead (changelog in [`v0.4.1.md`](v0.4.1.md)).
Of the nine spawns in completed questions, SH tagged 3 `hunter`, 6 `content` and 0 `metrics`.
In practice SH's COMMAND directives already say what the two tags say, and they say it about
the specific case in front of the senior:
- *hunter*'s "enumerate the population before filtering" shows up as Q329's "enumerate the
  FileUploaded and FileSyncUploadedFull events and establish, for each, the uploader identity"
  and Q217's "start by enumerating Bud's outbound [mail]".
- *content*'s "drill to raw events first" shows up as Q217's "prioritize raw SMTP/MIME
  content", Q329's "extract and inspect message content rather than scan for plaintext tokens"
  and Q328's "recover the file content".

A spawn tag is fixed for the senior's life, while the directive is rewritten every round along
with `scope_change`. The tag choice is also unstable: the same question, Q224, was tagged
`metrics` in the killed run and `hunter` in the completed one. `metrics` stays, because it
encodes a hard rule SH cannot enforce mid-round. `specialists.py` itself is **unchanged**: the
`--loop compiler` A/B control still tags `[HUNTER]`/`[CONTENT]` through it, and pruning there
would change the baseline the experiment is compared against.

**SH-turn cap (§13) — not binding; keep 5 / 8 / 12.** No question ended on `turns`. The two
that ran long ended on `rounds` with 10 and 9 of 12 turns used. With CLARIFY never issued, turns
track waves plus one or two, so the wave budget binds first. The only tier this smoke measured
is 1000 pt.

**`splunk_agent.py` output-ceiling comment (§13) — closed: keep 32768.** The old `splunk_agent.py:489`
claim is gone. `5268068` rewrote it into `token_limit_kwargs`'s docstring, which now says 32768
is "GLM-5.3's own output ceiling — the model cannot be given more". The GENERAL entry below
records a published max output of 131 072. Whether Featherless serves less than the model card,
as it does for the context window (256K against 1M), is unverified. The user closed this on
2026-09-18: the cap stays **32768**, because since `fd48d54`/`5268068` no senior has returned a
blank report, which was the failure the cap existed to fix.

## The one-line hypothesis

Replace the `planner → executor → joiner → REPLAN` loop with a **bounded conversation**:
a small number of question-scoped seniors stay alive, report often against a standard
template, and SH steers them — instead of being killed and having their replacements
re-briefed from zero.

## Two change categories

Every change in v0.4.0 is classified into exactly one of these, and the classification is
recorded in the same turn as the change.

**GENERAL** — lands on `main`, survives a failed experiment. A fix or improvement that
would be right regardless of which orchestrator is running: shared-module bugs, logging,
the usage tracker, the Splunk client, the worker graph, documentation.

**EXPERIMENT** — lives only on `exp/v0.4-conversational`. The conversation loop, the
six route schemas, the review rubric and its two gates, the report template, the thread
log, the context tracker, and the deletion of the joiner.

**Exit condition.** If the experiment fails, `git branch -D exp/v0.4-conversational` is
the entire revert — general changes are already on `main` and are untouched by it.

## Design summary

Detail lives in the spec; this is the shape.

**Loop.** SH spawns one senior. Each senior works up to 8 iterations, then emits a
templated markdown report. SH reads the whole parallel wave in **one** turn and issues one
route per senior. No joiner node, no `JOINER_SYSTEM_PROMPT`, no `REPLAN:` parse, no
`MAX_PLAN_ROUNDS`.

**Boundary rule, in both prompts.** *SH speaks in constraints and goals; the senior speaks
in evidence and SPL.* SH owns `scope_change` and nothing below it — that is how it can act
on a `NOT_FOUND` without writing a query, which is the job it cannot do.

**Six routes:** `SPAWN`, `RETIRE`, `COMMAND{continue|retry}`, `CRITIC`, `CLARIFY` (1-3
questions, answered from memory, no tools, does not consume a round), `ANSWER`.

CRITIC is its own route rather than a third COMMAND decision, because route-specific
prompt text has nowhere to live inside a single COMMAND block, and because `strict=True`
has no optional fields — a `flaw` inside COMMAND would be legally empty on a critic. Its
payload is `basis` (a closed five-value enum), `flaw`, `why_it_fails`, `fix_directive`
(free text, no SPL, no invented branch), `scope_change`. The enum is closed because SH has
no Splunk access: a free-text counter-example is an invitation to invent a dataset fact.
A doubt fitting none of the five is a CLARIFY, not a critic.

**Review rubric — SH-side, grades emitted.** R1 scope alignment, R2 progress, R3 answer
readiness, each `PASS`/`WEAK`/`FAIL`, written into SH's structured output per senior per
round. The senior never sees the rubric — it gets one line of intent at spawn and an
unchanged report template. R2 hard-fails in code when `novel_spl_count == 0` (a floor
enforced on SH's own grade would be dodgeable), and SH may additionally fail it on
judgement. Two gates: two consecutive R2 FAILs from either source blocks `continue`;
`R1 = FAIL` blocks `ANSWER`. Evidence-quality and calibration dimensions were considered
and dropped as duplicates of `extract_spl_and_sourcetypes` + the grounding gate, and of
`SOLVED_MIN_CONFIDENCE`.

**Exploration survives** from v0.3.0 unchanged, outside the conversation economy: it does
not consume one of the three senior slots, is not graded, and is capped at 1 per question.

**A question ends** on exactly three conditions: ANSWER accepted (grounded *and* source
report not `R1 = FAIL`), rounds exhausted, or SH turns exhausted. Both budgets are named
because clarify turns consume SH turns without consuming senior rounds, so either can run
out first.

**Seniors** are question-scoped, max 3 spawns per question, all retired at question end.
Spawning is demand-driven: SH starts with one and must justify each additional senior.
An `api_failed` or `runaway` retirement refunds its spawn slot.

**Budgets** key off `base_points`:

| Tier | Seniors | Rounds | Iters/round | Ceiling/senior | Question ceiling |
|---|---|---|---|---|---|
| 100 pt | 1 | 3 | 8 | 24 | 24 |
| 500 pt | 2 | 5 | 8 | 40 | 80 |
| 1000 pt | 3 | 8 | 8 | 64 | 192 |

**Known risk:** the 1000-pt ceiling is 2.4x the 80 senior-iterations measured today. It is
a ceiling, not a schedule, and early retirement is what is supposed to keep actuals far
below it — so the run instruments actual-vs-ceiling per question. If actuals track the
ceiling, the experiment has failed on cost regardless of score.

**Artifacts per question:** `conversation.md` (group-chat transcript),
`reports/senior_<n>_round_<r>.md`, `handoffs/senior_<n>_handoff.md`.

**Context management** is predictive and checked at round start: compact when
`current + 8 x mean_tokens_per_iteration` would exceed 80% of the window; alert the
operator at 70%. Compaction needs no new prompt — the senior's latest report is already
its compressed state.

**Context windows are recorded per model beside `PRICES_PER_1M`** in
`agent/v0/usage_tracker.py`, and the number recorded is the one the **provider serves**,
not the one the model card declares. `zai-org/GLM-5.3` = **256 000** (Featherless), against
a 1 048 576 checkpoint declaration. Round down when unsure: too low compacts early and
wastes a little, too high overflows mid-round and costs the round. A model added later
gets its served window looked up at the same moment `CLAUDE.md` already requires asking
for its price.

## Success criteria

Measured on a 5-question smoke test (`Q216 Q217 Q224 Q328 Q329`) against
`test_20260915_174228`:

1. **Score** beats 0/5.
2. **Cost per question** stays within ~2x of $0.272.
3. **Actual senior-iterations** track the 80 baseline, not the 192 ceiling.
4. SH is verifying, not rubber-stamping — now a table rather than a transcript read:
   grade distribution, `continue`-rate conditional on R2 grade, contradiction counts
   (`continue` after a FAIL, `ANSWER` from a WEAK-scope report), critics per `basis`, and
   the `novel_spl_count` distribution that answers the ceiling risk directly.

Per the active cost-limited-runs policy, **no full run without explicit user go-ahead.**
