## Key failure modes

### 1. Extractor credential censorship
The Llama-3.3-70B extractor treated any answer resembling a password, access key, or secret as a credential to refuse. This blocked at least 3 legitimate SIEM questions (Q220, Q303, Q320) and is a direct architectural defect. Fix: inject explicit instructions that CTF credential answers are legitimate and must not be filtered.

### 2. SH cross-question memory hallucination
For Q320 ("What is the password for the user created on the compromised endpoint?"), the SH recognized it as "same as Q303" from its persistent memory, produced a zero-delegation answer, and hallucinated that it already knew the answer was a password it could not provide. Fix: enforce delegation for all data questions regardless of cross-question memory.

### 3. Extractor format bleed
Q331 (IQR upper fence): the Senior computed `1368` correctly, but the Extractor echoed back `UF = 1368`. Fix: strengthen the extractor prompt to strip all labels and return bare numeric values.

### 4. Q304 host mis-scoping
The SH used `hoth` (the Linux host) as "the compromised endpoint" when the question refers to the Windows endpoint. The correct answer is `svcvnc` (Windows EventCode 4720), not `tomcat7` (Linux useradd). Fix: SH should route Q304 to a Windows-endpoint-scoped search.

### 5. High-point questions requiring external knowledge
Q213 (Symantec severity), Q223 (Ubuntu codename), Q302 (Symantec discovery date) require looking up information on external websites not present in the dataset. These are structurally unanswerable without web search capability.
