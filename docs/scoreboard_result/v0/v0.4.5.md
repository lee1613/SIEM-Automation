## Memory and resume audit

- **Every recorded question is in memory.** All 50 have a `memory/<QID>.json` with a non-empty
  digest and an entry in `sh_history.pkl`, and both are in question order. 43 of them are
  summarized (`memory/swapped.json`), across six swaps: at Q224, Q307, Q314, Q318, Q322 and Q328.
- **A resume rebuilds the same prompt.** A resume reloads `sh_history.pkl`, `memory/*.json`,
  `memory/swapped.json` and `case_file.json`, which hold exactly the state at the pause. A question
  that was in flight continues from `resume_state/<QID>/snapshot.pkl`, saved at a turn boundary.
  Every restarted question's opening prompt matched its first attempt to the token: Q218 133,848,
  Q223 153,721, Q317 159,328, Q328 120,823.
- **No replay function exists.** To rebuild the exact prompt SH saw for, say, Q216, you need the
  state as it stood after Q215:
  - history and memory filtered to earlier questions (both are keyed by qid);
  - `swapped.json` recomputed by replaying the swaps in order;
  - the case file filtered by `source_qid`/`qid`. A finding's status only changes through
    `reconcile_findings` for its own question, so this filter is exact.

  To check that a rebuild works: the rebuilt Q216 prompt must come to exactly 109,448 tokens, the
  figure logged at the time.
