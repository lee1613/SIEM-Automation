### Root cause of the cost blowup

| Model | Role | Input tokens | Output tokens | Est. USD |
|-------|------|:------------:|:--------------:|:--------:|
| gpt-5.4 | SH planner/joiner/verifier | 1,219,875 | 41,231 | $4.83 |
| GLM-5.2-fp8 (Vultr) | Senior workers | **28,161,620** | 837,181 | **$26.53** |
| Qwen3.6-27B (Vultr) | Extractor | 15,035 | 512 | $0.00 (untracked price) |
| **Total** | | **29,396,530** | **878,924** | **$31.36** |

Senior workers are 85% of total cost — 51x v1.1's whole-run token volume. The
`MAX_HISTORY_MSGS=24` window added this run caps the SH's own context, but each
Senior worker still runs its own independent tool-call loop up to
`iter_budget(points)` (25 iterations for >=500pt questions), and every "too_big"
or "failed" delegation triggers a JOINER REPLAN → fresh Senior workers with no
carried context. `failed_delegations: 62` (v1.1: 1) means the run spent most of
its 25-iteration budgets on workers that never produced a usable answer — that's
where the tokens went, not on more thorough investigation.

**v1.3 candidate fix**: cap replan rounds more aggressively for high-value
questions, or make a failed/too_big worker's transcript feed the next worker as
context instead of a blind fresh restart. Verify against `failed_delegations`
trending toward v1.1's near-zero baseline before declaring it fixed.
