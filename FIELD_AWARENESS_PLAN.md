# Plan: Equip the SIEM Agent with Field & Syntax Awareness

## Context

The agent currently fails on questions where the answer is not in an obvious field (e.g. Q333 — CVE of exploit on host hoth). Root causes:

1. **Field names are guessed, not known.** The system prompt has a sparse, hardcoded sourcetype→field map. When the model guesses wrong (`CVE`, `user` instead of `userIdentity.userName`), it gets 0 results and gives up.
2. **No schema introspection tool.** The model has no way to ask "what fields actually exist in this sourcetype?" — the equivalent of SQL's `SELECT * FROM INFORMATION_SCHEMA.COLUMNS`.
3. **No retry strategy.** On 0 results the model either repeats the same query or surrenders instead of pivoting to field discovery.

This is the same structural problem as Text-to-SQL agents: the model needs ground-truth schema context before writing queries, not after they fail.

---

## Recommended Approach: Three Layers

### Layer 1 — `get_fields` tool (dynamic schema introspection)

Add a new tool to `splunk_agent.py` and a new method to `splunk_client.py` that runs Splunk's `fieldsummary` command — the direct SPL equivalent of SQL's `INFORMATION_SCHEMA`.

**New tool definition:**
```
get_fields(sourcetype, index="botsv3", min_coverage=10)
```

Runs:
```spl
search index=botsv3 sourcetype=<X> | fieldsummary | where coverage >= 10 | table field, count, coverage | sort -coverage
```

Returns a ranked list of real field names with how often they appear. The model calls this when it is unsure of field names before writing a data query.

**Analogy to SQL:**
| SQL | SPL |
|---|---|
| `SELECT column_name FROM INFORMATION_SCHEMA.COLUMNS WHERE table_name='X'` | `sourcetype=X \| fieldsummary \| table field` |

**Changes required:**
- `agent/splunk_client.py` — add `get_fields(sourcetype, index, min_coverage)` method
- `agent/splunk_agent.py` — add `get_fields` entry to `TOOLS` list and handle it in `execute_tool()`

---

### Layer 2 — Pre-built field manifest (static fast-path)

Run `get_fields` once for each major BOTSv3 sourcetype and save the output as `agent/botsv3_field_manifest.json`. Inject a condensed version of this into the system prompt so the model has accurate field names without needing a live Splunk call for common sourcetypes.

**File to create:** `agent/botsv3_field_manifest.json`

Sourcetypes to pre-generate (the ones that appear in BOTSv3 questions):
- `aws:cloudtrail`
- `linux_secure`
- `WinEventLog` / `XmlWinEventLog`
- `stream:http`, `stream:dns`, `stream:smtp`
- `ms:o365:management`, `ms:aad:signin`, `ms:aad:audit`
- `osquery:results`
- `PerfmonMk:Process`
- `iis`

The manifest is generated by running a one-off Python script (`agent/build_manifest.py`) against the live Splunk instance. It does not need to be regenerated unless the dataset changes.

---

### Layer 3 — Few-shot SPL examples in system prompt

Extend the system prompt with 1–2 concrete working examples per sourcetype. This guides syntax (quoting, dot-notation for nested fields, correct command names) without requiring the model to infer them from description alone.

Example addition to system prompt:
```
Working examples:
- aws:cloudtrail IAM users:     index=botsv3 sourcetype="aws:cloudtrail" | stats count by userIdentity.userName
- Failed Windows logins:        index=botsv3 sourcetype=WinEventLog EventCode=4625 | stats count by host, User
- DNS queries from host:        index=botsv3 sourcetype="stream:dns" host=BSTOLL-L | stats count by query
- Linux commands run as root:   index=botsv3 sourcetype="linux_secure" user=root | stats count by host
```

**Change required:** extend `SYSTEM_PROMPT` string in `agent/splunk_agent.py`

## Implementation Steps

### Step 1 — Add `get_fields` to `splunk_client.py`

```python
def get_fields(self, sourcetype: str, index: str = "botsv3", min_coverage: int = 10) -> dict:
    """Return real field names for a sourcetype, ranked by coverage."""
    return self.search(
        f'index={index} sourcetype="{sourcetype}" | fieldsummary | where coverage >= {min_coverage} | table field, count, coverage | sort -coverage',
        earliest="0",
        max_results=200,
    )
```

### Step 2 — Add `get_fields` tool to `splunk_agent.py`

Add to `TOOLS` list:
```python
{
    "type": "function",
    "function": {
        "name": "get_fields",
        "description": (
            "Discover what fields actually exist in a sourcetype — use this BEFORE writing a query "
            "when you are unsure of field names. Equivalent to SQL INFORMATION_SCHEMA. "
            "Returns fields ranked by how frequently they appear (coverage %)."
        ),
        "parameters": {
            "type": "object",
            "properties": {
                "sourcetype": {"type": "string", "description": "e.g. 'aws:cloudtrail', 'linux_secure', 'WinEventLog'"},
                "index":      {"type": "string", "default": "botsv3"},
                "min_coverage": {"type": "integer", "description": "Min % of events that must have the field (default 10)", "default": 10},
            },
            "required": ["sourcetype"],
        },
    },
}
```

Handle in `execute_tool()`:
```python
elif tool_name == "get_fields":
    result = splunk.get_fields(
        sourcetype=tool_input["sourcetype"],
        index=tool_input.get("index", "botsv3"),
        min_coverage=tool_input.get("min_coverage", 10),
    )
```

### Step 3 — Create `agent/build_manifest.py`

One-off script that calls `get_fields` for each major sourcetype and writes `agent/botsv3_field_manifest.json`.

```python
#!/usr/bin/env python3
"""Run once to generate botsv3_field_manifest.json from live Splunk."""
import json, os
from dotenv import load_dotenv
from splunk_client import SplunkClient

load_dotenv()
splunk = SplunkClient(os.getenv("SPLUNK_HOST"), os.getenv("SPLUNK_USER"), os.getenv("SPLUNK_PASS"))

SOURCETYPES = [
    "aws:cloudtrail", "linux_secure", "WinEventLog", "XmlWinEventLog",
    "stream:http", "stream:dns", "stream:smtp",
    "ms:o365:management", "ms:aad:signin", "ms:aad:audit",
    "osquery:results", "PerfmonMk:Process", "iis",
]

manifest = {}
for st in SOURCETYPES:
    print(f"  {st}...")
    result = splunk.get_fields(st)
    manifest[st] = [r["field"] for r in result.get("results", [])]

with open("botsv3_field_manifest.json", "w") as f:
    json.dump(manifest, f, indent=2)

print("Written: botsv3_field_manifest.json")
```

Run from `agent/` directory:
```bash
cd agent
python build_manifest.py
```

### Step 4 — Inject manifest summary into system prompt

Load `botsv3_field_manifest.json` at startup and prepend a condensed field reference to the system prompt. Replace the hardcoded field section with dynamically loaded ground-truth field names.
